# 人工智能的新转折：从会回答到能做事

上一篇从早期的规则和神经网络，讲到 Transformer 与 ChatGPT。ChatGPT 让更多人发现，AI 可以用日常语言交流。但如果我们希望它查最新资料、处理复杂问题，甚至操作软件，仅仅“会聊天”还不够。

2023 年以来，研究和产品开始把语言模型与检索、推理和工具连接起来。变化的重点，是逐渐把 AI 从“给出一个回答”，扩展为“围绕目标完成一串步骤”。这些阶段彼此重叠，并不是每年突然换一种全新技术。

## 1. 2023 年起：RAG 和工具调用让 AI 接触外部信息

大型语言模型的知识主要来自训练过程，可能过时，也可能不知道某个组织的内部资料。检索增强生成（RAG）会先从指定资料库中找相关内容，再把找到的信息交给模型参考后回答。

工具调用则让模型能够请求软件执行某个操作，例如查数据库、读取构建日志或调用 API。向量数据库常用来帮助检索意思相近的文本；MCP（Model Context Protocol，模型上下文协议）于 2024 年提出，目标之一是用较一致的方式连接模型和外部工具、数据源。

以 DevOps 为例，AI 不再只能根据用户粘贴的一小段 Jenkins 日志猜原因。连接适当的系统后，它可以检索完整日志、查看相关代码变更，再据此整理可能的故障原因。检索和调用工具能提供更多依据，但结果仍需要检查，尤其当外部资料不完整或工具返回异常时。

有了更多信息和工具，另一个问题变得更明显：面对需要多个步骤的难题，模型能不能花更多力气检查和推敲？

## 2. 2024 年起：推理模型尝试为难题投入更多计算

以 OpenAI o1 为代表的一类推理模型，会在生成最终答复前使用额外计算处理问题。相关训练和推理方法探索如何改善数学、编程和复杂逻辑任务的表现。Test-time compute（测试时计算）可以简单理解为：模型作答时，根据任务投入更多计算资源。

这代表一种不同于单纯扩大模型规模的探索：有时，让模型在回答前多处理一会儿，也能帮助它应对更复杂的问题。不过，额外计算并不保证答案正确，也会带来时间和成本。模型仍需要可靠的信息，以及能判断答案是否站得住脚的验证办法。

当模型能处理较复杂的问题，也能接触外部工具，人们便开始尝试让它连续完成多个步骤，而不是每一步都等人重新下指令。

## 3. 2025—2026 年：Agent 开始进入实际工作流程

Agent（智能体）通常指能够围绕一个目标，规划步骤、调用工具、根据结果调整做法的 AI 系统。这个想法并非最近才出现；早期智能体研究、ReAct 方法和工具调用都早于 2025 年。近年的变化，是模型能力、工具生态和实际执行环境逐渐成熟，更多产品开始尝试把这些能力组合进工作流程。

例如，可以请一个 DevOps Agent：“检查今天失败的 Jenkins Pipeline，找出最可能的根因，并整理报告。”一个经过授权和配置的系统可能会：

1. 查询相关 Jenkins 实例，收集失败任务和日志。
2. 找出日志中的关键错误，并查看近期代码变更。
3. 比较证据，列出较可能的原因和仍不确定的部分。
4. 生成根因分析报告；若被授权，再创建后续任务。

它不再只给一段解释，而是尝试把工作推进到一个可交付的结果。要做到可靠，仍需要清楚的权限边界、过程记录、结果验证，以及失败时暂停或恢复的机制。多步骤系统还可能在早期判断出错后一路延续错误，因此“能执行”不等于“可以不经检查地执行”。

## 把长历史和近期变化接起来

回看更长的历史，AI 曾先依赖人写的规则，后来学会从数据中找规律，再借助深度学习和 Transformer 获得更广泛的语言能力。ChatGPT 把这种能力带给大众；RAG、推理模型和 Agent 则尝试让它取得所需信息、处理更复杂的问题，并通过工具采取行动。

可以把这种变化概括成三个便于理解的阶段：

| 阶段 | 人提供什么 | AI 主要产出什么 |
| --- | --- | --- |
| 早期 AI | 规则和数据 | 判断或预测 |
| 大模型普及 | 提示词和上下文 | 内容和答案 |
| Agent 系统 | 目标、工具和权限 | 多步骤任务结果 |

这只是帮助理解的划分，并非学界公认的正式分期；不同方法至今仍会同时使用。

## 下一阶段的关键：可靠地完成工作

过去，人们常用模型是否答对来衡量进步。现在，任务型 AI 还需要回答另一个问题：它能否在合适的权限内，可靠地把事情做完？

以软件工程和 DevOps 为例，重要的不只是写出更好的提示词，还包括给 Agent 合适的上下文、连接正确的工具、把目标拆成步骤、限制可执行的操作，并检查最终结果。实践中，这些环节共同决定 Agent 能否从演示走进真实工作。

因此，Agentic AI 可以看作 Transformer 和大语言模型之后的一条重要工程方向：模型本身仍然重要，但能否把模型、信息、工具与验证机制组合好，同样决定它最终能做什么。
