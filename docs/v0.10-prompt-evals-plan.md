# v0.10 — Prompt Evals Harness Plan

> **Status: BUILT (2026-10-18) — layer 1 live and wired to `.githooks/pre-push`;
> layer 2 wired, calibrated, opt-in.** The harness ships as `video prompts eval`.
> Deviations from this doc and from §7's build gate are recorded in §8.
>
> All five cases carry a recorded baseline, including both `storyboard`
> cases — those only became judgeable after the three defects in §8 gap 2 were
> fixed, and every one of those defects was also a live `video storyboard`
> failure.

## 1. Problem

Since v0.8 every prompt body lives in `packages/prompts/prompts/`, which
made prompt iteration cheap — and made the lack of a quality regression
harness the bottleneck:

- Tests pin **structure** (`toBe(SYSTEM_PROMPT)`, `toContain` phrases,
  placeholder fills), not **behavior**: nothing says "the drafter still
  produces 20-scene articles with a tension-opening hook".
- The only signal that a prompt edit helped or hurt is watching a render.
  That is slow (~minutes), subjective, and per-project — a regression in
  the storyboard agent surfaces as a bad 鸿门宴 render, not a red test.
- `RunRecord.prompt_hash` gives us lineage (which prompt version ran), but
  no score attached to a hash, so history cannot be compared.

## 2. Goals / non-goals

**Goals**

1. A golden set per agent: fixed inputs → recorded expectations.
2. Two evaluation layers: structural (offline, CI-safe) and judged
   (LLM rubric, local/opt-in).
3. A report that pins `prompt_hash → scores` so prompt changes are
   attributable and comparable over time.
4. Golden cases sourced from real failures, not invented ones.

**Non-goals**

- Full end-to-end render evals (cost + time; `video make --dry-run` impact
  and QA reports already cover that surface).
- Replacing the human gate. Evals inform prompt edits; humans approve them.
- Auto-rewriting prompts from eval results.

## 3. Golden set

**Location:** `packages/prompts/evals/<agent>/<case-id>.yaml` — beside the
prompts they exercise, so prompt + eval travel in one review. The harness
itself lives in `packages/cli` (`video prompts eval`) because `@video/prompts`
stays dependency-free and the CLI already aggregates every agent package.

**Fixture shape** (per case):

```yaml
id: draft-opens-with-tension
agent: draft # which prompt + buildMessages
input: # the exact AgentInput/DraftInput for the case
  topic: "鸿门宴"
  audience: "对历史感兴趣的普通观众"
  language: zh-CN
  duration: 300
expects: # judge rubric, 0-10 axes like article-review
  - axis: hook-tension
    min: 7
  - axis: scene-count-fits-duration
    min: 8
provenance: # why this case exists — the failure it encodes
  source: learn-session 2026-10-16 lesson "scene 4 carried fake signage"
recorded: # last judged result (updated by the harness)
  prompt_hash: sha256:…
  scores: { hook-tension: 8, scene-count-fits-duration: 9 }
```

**Sourcing rules** (real failures first):

1. `video learn` corroborated lessons that name a prompt-behavior fix.
2. `retrospect.md` suggestions that were accepted and fixed — the pre-fix
   article is a negative case.
3. QA report findings with a prompt-side root cause (caption overflow,
   unsupported-claim drift).
4. Seed bootstrap: ~3 cases per agent from `projects/benchmark-v01` +
   `projects/鸿门宴` history, hand-labeled once.

Target: **5-10 cases per agent, capped.** A golden set nobody prunes is a
flaky suite.

## 4. Harness — `video prompts eval`

```
video prompts eval [--agent <name>] [--case <id>] [--judge glm]
                   [--offline] [--update-recorded]
```

**Layer 1 — structural (default, offline, runs in CI):**
for each case, `buildMessages(input)` and compare against a committed
message snapshot (`evals/<agent>/__snapshots__/<case>.envelope.yaml`:
roles + content hashes + context-block layout). Catches: accidental prompt
body edits, context-block ordering regressions, truncation-limit changes.
No API keys, no cost, deterministic.

**Layer 2 — judged (opt-in, local):** send the case's messages to the
provider and score the response with a rubric judge. Reuse the
article-review judge pattern (`packages/draft/src/article-review.ts`):
0-10 axes with calibrated anchor points, JSON-only output, scores coerced
and clamped by us, `total` never trusted from the LLM. The judge prompt
itself lives in the registry (`evals-judge.md`) like every other prompt.

**Report:** `packages/prompts/evals/report.yaml` — one row per case:
`{case, prompt_hash, scores, verdict}`. `--update-recorded` refreshes the
`recorded:` block in fixtures (the new baseline) after a deliberate prompt
change; without it, a case scoring below `min` fails the run. Because rows
carry `prompt_hash`, comparing two runs attributes the delta to the exact
prompt edit.

## 5. Cost & CI posture

- CI (`pnpm test`): layer 1 only. New test file
  `packages/cli/src/prompt-evals.test.ts` walks `evals/` — every fixture
  must have a snapshot, every snapshot a fixture (same two-way orphan
  discipline as the registry).
- Layer 2: golden-size × one generation + one judge call per case
  (~20 calls for a full run at 10 cases × 2 agents) — run locally before
  landing a prompt change, like `benchmark:verify`.
- Providers: judge runs on the review-role provider (GLM default); no new
  credentials.

## 6. What each existing piece contributes

| Existing                                              | Role in the harness                                              |
| ----------------------------------------------------- | ---------------------------------------------------------------- |
| `RunRecord.prompt_hash` / `sha256OfMessages`          | lineage key for report rows                                      |
| article-review judge (`ARTICLE_REVIEW_SYSTEM_PROMPT`) | rubric-judge pattern to copy (anchors, clamping, JSON-only)      |
| `video learn` lesson store                            | primary golden-case source (§3)                                  |
| `packages/prompts` registry + coverage test           | evals live beside prompts; same orphan guard extends to fixtures |
| `runScoredDraft` retry loop                           | precedent for threshold-based fail/regenerate semantics          |

## 7. Build triggers (when to actually build this)

Build when any of these fires — not before, to avoid harness-without-users:

1. A deliberate prompt-iteration cycle starts (e.g. tuning `draft-article.md`
   for hook quality) — the eval pays for itself in the first A/B.
2. The learn store holds ≥ 5 corroborated lessons that name prompt behavior
   (enough real negative cases to seed the golden set).
3. A quality incident that a judged eval would have caught pre-render.

Estimated build: ~1 day (fixtures + envelope snapshots + judge verb + report).

## 8. What shipped, and where it differs from this doc

**Built before §7 fired.** As of this commit the gate is not satisfied:
`learnings/lessons.yaml` holds 2 lessons, neither `highConfidence`, and
neither names drafter or storyboard behavior (§3 sourcing rule 1 needs ≥5).
The build happened because it was explicitly requested, not because a
trigger fired. The golden set is therefore **seed-only** — see below.

**Differences from the design above:**

| Doc said | Shipped | Why |
| --- | --- | --- |
| Golden set of 5-10 cases per agent | 3 `draft` + 2 `storyboard` | §3's own seed bootstrap number ("~3 cases per agent"), not its steady-state target. §3 also says a golden set nobody prunes is a flaky suite — an unpruned seeded set is worse. |
| `evals-judge.md` with the rubric | Same, but the axes come from each fixture's `expects` | A fixed three-axis rubric would not fit two agents with different failure modes. The judge prompt states the anchors and takes the axis list per call. |
| `--offline` as the CI default | No flag ⇒ layer 1 only; `--judge` is the opt-in | §5 asks for layer 1 in CI and layer 2 local/opt-in. Making `--judge` the switch means a plain `video prompts eval` can never spend tokens by accident. |
| Snapshot regeneration implied by `--update-recorded` | Separate `--update-snapshots` | They guard different things: `--update-recorded` re-baselines the *judged score*; `--update-snapshots` re-baselines the *prompt fingerprint*. Merging them would let a deliberate score regression silently re-bless the prompt too. |
| `evals/report.yaml` rows carry a verdict | Same, plus `structural` and `judged` as separate columns | A run that skips layer 2 must not render as an unqualified pass. |
| §6 `sha256OfMessages` reuse | Shared, moved to `@video/prompts` | Six CLI commands each hold a private copy (review, script, research, storyboard, motion, youtube). The harness imports the shared one so report rows join real `prompt_hash` values. The six copies are untouched — deduping them is a separate change. |
| §5 "run locally before landing a prompt change, like `benchmark:verify`" | Layer 1 wired into `.githooks/pre-push`; layer 2 opt-in | See gap 3 — layer 2 cannot meet a push gate's latency budget. |

**Known gaps:**

1. **The one recorded real failure is not covered.** The image-prompt
   signage lesson (`learnings/lessons.yaml`, seen 2×) belongs to
   `expandScenePrompt`, which builds its messages inline inside a
   project-writing function — giving it a `build()` adapter means
   extracting the message assembly. Out of scope here.
2. **Storyboard validation — three defects, all fixed.** Found by
   `video prompts eval --judge`, and all three were live `video storyboard`
   failures, not only eval problems. A strict schema plus an inventive model
   discards an entire storyboard over one bad field.
   - *Enum gap.* GLM emitted `slide-left` / `slide-right` / `slide_left` /
     `slide-in-both-sides` / `zoom-out`, none of which
     `ANIMATION_ENTRANCE_SYNONYMS` carried. `coerceAnimationEntrance` now
     accepts a directional qualifier on a known cluster head (`slide-*` →
     `slide`, `zoom-*`/`scale-*` → `scale`, `wipe-*` → `draw`, `fade-*` →
     `fade`) plus bare vertical-translate verbs (`rise`, `lift`, `elevate`,
     `ascend`). A non-directional qualifier still throws, so the "reject real
     bugs" property in the module header survives.
   - *Unstated shape.* The model invented unknown keys under `style` —
     `notes`, then `art_style` and `palette` together. `prompts/storyboard.md`
     rule 3 now states that `style` accepts only `theme`, and that `brand` is
     a structured object to omit.
   - *No repair path.* `callAgent` had none: one invalid field killed the
     run. It now makes one repair pass, feeding the validator's own
     `field: message` list back and telling the model to change nothing else.
     The repair messages are excluded from `AgentResult.messages`, so
     run-record `prompt_hash` still describes the prompt. Costs one extra
     call, only on failure.

   A lesson in the second bullet: naming `brand` as allowed — without saying
   it is an object — *invited* `brand: "cinematic"` on the very next run.
3. **Layer 2 is opt-in at the push gate.** Measured on GLM, 2026-10-18,
   three draft cases: generation 95-134s per case, rubric judge 20-26s
   per case, ~160s wall at concurrency 4. The generation is irreducible,
   so `.githooks/pre-push` gates on layer 1 (~1s) by default and adds
   layer 2 only under `PROMPT_EVAL_JUDGE=1`.
4. **Thresholds are calibrated, not aspirational.** Every `min` is
   *observed floor − 1* over ≥3 judged runs per axis. Two authored axes were
   removed rather than given a meaningless threshold: the draft case's
   `revision-addresses-feedback` (6, 5, 6, 5, 3) and the storyboard case's
   `claims-cited-in-visuals` (3, 4, 6, 6). Both swung 3 points across runs of
   the *same* prompt — a spread that tracks judge variance, not draft quality.
   The generic anchors in `evals-judge.md` do not calibrate them; re-add after
   giving the judge per-axis anchors.
5. **All five fixtures carry a `recorded:` baseline**, and both `storyboard`
   cases are inside the judged gate — only possible because defect 2 above is
   fixed.
6. **The GLM provider is not perfectly reliable.** Observed about once per six
   judged runs: a `contentFilter` 400 on the assistant turn. That is why exit 2
   exists and why the hook does not block on it.
7. **Layer 2's live provider path has no unit test.** `scoreAgainstRubric`,
   `verdictFor`, `verdictExitCode` and `clampAxis` are tested against
   synthetic payloads and a stub `Provider`; the generation half runs only
   in a real `--judge` run.
8. **The image-prompt agent is inside the judged gate (v0.10.1).** A third
   adapter, `image-prompt`, drives the brief expander through the pure
   `expandSceneBrief` path (no cache, no sidecar writes). Its golden case is
   the era-anchoring regression: an era-poor guard scene that produced a
   "late Ming dynasty, 1620" brief when the setting was absent. Axes
   `era-and-region-named` (min 8) and `period-dress-specific` (min 6),
   calibrated over n=3. One run in three hit the provider timeout —
   infrastructure, exit 2, not a scored sample.
9. **The rendered image was measured, not assumed (v0.10.1).** Five real
   MiniMax renders (four era-anchored + one no-setting control), judged
   blind by a vision classifier (`gpt-6-luna`):

   | probe | setting | western-euro | east-asian | reads as Tang |
   | --- | --- | --- | --- | --- |
   | guard (lone, night) | yes | 0.00 | 0.99 | 0.21 (period-unclear Chinese) |
   | beacon soldier | yes | 0.02 | 0.99 | 0.66 |
   | two ranks of officials | yes | 0.00 | 1.00 | 0.85 |
   | three commanders | yes | 0.00 | 0.98 | 0.81 |
   | guard (control) | no | 0.04 | 1.00 | 0.90 (brief said Ming) |

   Western contamination — the reported bug — is 0.00-0.04 across all five,
   including the control. Ethnicity renders East Asian at 0.98-1.00. The
   residual is dynasty precision, not race: one lone night figure read
   period-unclear (0.21), plausibly because the `editorial` style preset
   asks for "stylized simplified human figures", which flattens period
   markers on a single small subject. That is an art-direction trade-off,
   not an anchoring failure. The measurement is one-shot, not a gate:
   judging pixels costs a vision model per frame and stays manual.
10. **Brief format is six labelled lines (v0.10.2).** Per explicit request,
   `scene_##.prompt.txt` carries `1. Subject:` ... `6. Constraints:` instead
   of the historical single paragraph, with the camera-framing / lighting-
   direction / concrete-style / quiet-space / depth-layer / material /
   locked-palette guidance folded into the corresponding lines, and the
   practical exclusions (no background people, no cropped hands, face
   unobstructed, no modern objects in period settings) added to Constraints.
   Two measured consequences:
   - `MAX_BRIEF_CHARS` went 700 -> 800 -> 1400. The labelled format is longer
     than the paragraph it replaced; at 800 every measured brief clipped and
     one lost Constraints entirely, at 1100 all three still sliced
     mid-Constraints. At 1400 with the prompt instructing 500-1000, three
     measured briefs landed at 979-1203 chars, complete, with full exclusion
     sentences. The cap is a runaway guard, not a target.
   - `IMAGE_PROMPT_REVISION` -> "4", so paragraph-era cached briefs are
     regenerated rather than reused.
