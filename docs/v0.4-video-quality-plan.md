# v0.4 — Visual & Publishing Quality Plan

> Source: read-through of the v0.3.10 codebase on 2026-10-03 against the
> current user-facing workflow (`video new → video draft → video approve storyboard
> → video make`). Scoped to "help users create better videos" — does NOT
> touch the two-file human-gate principle (`article.md` + `audio-config.yaml`,
> doc `AI_Video_Factory_Design_and_Plan_v1.1.md` §65).

## Why this plan exists

The recommended 4-command path (`new / draft / approve storyboard / make`)
delegates every visual decision to a single LLM call (`video draft`) plus
two derived files (`storyboard.yaml` + per-scene images). Three concrete
gaps degrade video quality today:

1. **Captions** — the article's `caption` field is dropped at the render
   layer; the `CaptionsOverlay` is never wired into the auto-generated
   storyboard. Viewers in noisy environments can't follow narration.
2. **Visual variety** — the draft prompt lists 18 visual formats and
   forbids repetition, but `articleToStoryboardYaml` emits the same
   `Title` + `AnimatedIllustration` template for every scene. The LLM's
   variety instructions are silently dropped.
3. **Image prompts** — `video make` feeds the article's 80-char `visual:`
   field straight to `image-01`. That text was written for keyword
   matching against the `AnimatedIllustration` shape vocabulary, not for
   image generation. Result: mediocre AI images + thumbnails that
   contradict the YouTube agent's own "no text overlay" rule.

Two secondary gaps:

4. **Hook ↔ YouTube package coherence** — `video youtube` produces
   `thumbnail_prompt` + `shorts_hook` without ever seeing
   `article.md`'s hook. The LLM wastes context and contradicts
   downstream rules.
5. **Mock Shorts** — `shorts-hook.txt` is generated then ignored; the
   mock path crops `final.mp4` from second 0 instead of the hook
   boundary.

Two experience gaps:

6. **QA findings invisible** — `qa/render-report.json` exists, but
   `video final` doesn't auto-run QA and `video status` doesn't surface
   findings.
7. **CLI discoverability** — `video --help` dumps 25+ verbs; the README's
   "minimal API" isn't reflected in help output.

This plan ships fixes for all seven as independently shippable, runnable
increments. Each preserves the human-gate principle and is verified with
an actual rendered before/after comparison (or its unit/integration test
equivalent where the change is local).

## Guiding constraints (carried over from doc §65)

- AI generates · Human decides · Code renders · Git remembers.
- The two human-edit files (`article.md`, `audio-config.yaml`) remain
  the only files a user must hand-edit.
- Every derived file is re-derivable from those two; re-running
  `video make` after edits must skip work whose outputs are newer than
  its inputs (idempotency preserved).
- No auto-publishing, no auto-approve.

## 1. Goal & success criteria

By the end of v0.4, a user running only `video draft <topic>` and
`video make <topic>` on a fresh project should get a video with**:

   - [x] On-screen captions that follow narration timing (default
     ON, `--no-captions` opt-out).
   - [x] Visual variety: at least 3 distinct VDSL components across
     a 6-scene video (instead of 1).
   - [x] Image prompts appropriate for the chosen provider:
     - `--image-provider mock` → unchanged behavior.
     - `--image-provider minimax` → expanded, style-tagged prompts
       with explicit anti-text-overlay rules.
   - [x] A YouTube package (`thumbnail_prompt`, `shorts_hook`,
     `chapters`, `description`) that visibly derives from the
     article's hook, not from a re-read of the whole script.
   - [x] `video final` exits non-zero with a readable gate message if QA
     reports `level: error` findings.
   - [x] `video status` surfaces QA finding count next to the current
     stage mark.
   - [x] `video --help` shows the minimal-API banner above the verb list.

And none of these require the user to hand-edit any file beyond the
two canonical human-edit artifacts.

### Verification gate

`npm run acceptance` (§62.4) must still pass. Additionally a new
`npm run video-quality:plan` script renders the benchmark project
(`projects/benchmark-v01`) under v0.3.10 (baseline) and under v0.4,
then asserts:

- Captions SRT exists and covers narration duration (was missing).
- Storyboard uses ≥3 distinct components for the 6-scene benchmark
  (was 2 — `Title` + `AnimatedIllustration`/`ImageBackground`).
- QA report `findings[]` count ≤ baseline (no regression).

### T1 · Auto-captions from article narration
**Files**: `packages/draft/src/schemas.ts`, `packages/cli/src/draft-command.ts`,
`packages/cli/src/make-command.ts` (no change), `packages/draft/src/index.ts`.
**Goal**: every auto-generated storyboard has `captions: { source: narration }`
unless the user passes `--no-captions` (new flag on `video draft`).

**Steps**
1. Add `noCaptions?: boolean` to `ArticleFrontmatterSchema` (optional,
   passthrough).
2. In `articleToStoryboardYaml` (`packages/draft/src/schemas.ts:75-89`),
   emit `    captions:\n      source: narration` after `visual:` unless
   the new flag is true.
3. In `packages/draft-command.ts`, accept `--no-captions` and stamp the
   parsed article's frontmatter (NOT a separate config file).
4. Confirm `CaptionsOverlay` is already wired into the Remotion root
   (`packages/video-renderer/src/Root.tsx`); if not, wire it so SRT
   cues are auto-loaded from `captions/<lang>.srt`.

**Acceptance**
- `video draft demo` (no `--no-captions`) → `storyboard/storyboard.yaml`
  contains `captions: { source: narration }` for every scene.
- `video draft demo --no-captions` → no `captions:` block.
- The existing `writeCaptionsSrt` step in `@video/make` continues to
  produce `captions/<lang>.srt` (no change), the overlay now consumes
  it.

**Verification**
- Unit: `packages/draft/src/schemas.test.ts` — new cases for both
  flag states.
- Integration: `packages/cli/src/draft-command.test.ts` (or new file)
  exercises end-to-end → SRT file exists and cue count == scene count.
- Smoke: `node packages/cli/dist/index.js draft demo --dry-run`-equivalent
  not yet supported; instead run real `video draft demo` on a tmpdir and
  read back `storyboard.yaml`.

### T2 · Visual-variety classifier
**Files**: new `packages/draft/src/visual-classifier.ts`,
`packages/draft/src/schemas.ts`, `packages/draft/src/index.ts`.
**Goal**: pick a VDSL component per scene based on the article's
`visual:` keyword set, replacing the unconditional
`Title` + `AnimatedIllustration` mapping.

**Vocabulary → component map** (deterministic, regex-based, no LLM):

| Keyword cluster                              | Component             |
|----------------------------------------------|-----------------------|
| `database`, `表`, `schema`, `存储`            | `Callout` (kind=data) |
| `network`, `网络`, `flow`, `pipeline`, `流水线`| `FlowChart`           |
| `compare`, `对比`, `versus`, `vs`, `差异`     | `Comparison`          |
| `code`, `terminal`, `代码`, `console`         | `Terminal`            |
| `timeline`, `年表`, `历史`, `年代`             | `Timeline`            |
| `formula`, `公式`, `equation`, `math`        | `Expression` (or `Callout` if missing) |
| `process`, `step`, `步骤`, `流水线`           | `FlowChart`           |
| `list`, `列表`, `bullet`, `要点`              | `Illustration`        |
| `quote`, `引用`, `引文`                       | `Callout` (kind=quote)|
| first scene (id=1)                            | `Title` (unchanged)   |
| fall-through                                 | `AnimatedIllustration` (unchanged) |

**Steps**
1. Add `visual-classifier.ts` exporting
   `pickVisualComponent(visual: string, isFirst: boolean): ComponentChoice`.
2. Refactor `articleToStoryboardYaml` to call the classifier. The
   first-scene rule is preserved (always `Title`); other scenes go
   through the classifier.
3. Each component's required props differ. The current mapper emits
   `text` only; for `FlowChart` / `Comparison` / `Terminal` / `Timeline`
   we need at least the right prop key set. Strategy: emit minimal
   valid props (`text: caption`) for new components — the existing
   components accept unknown props (they're rendered by name; missing
   props → empty fields). Document this in the prompt so the LLM
   knows to keep `caption` short.
4. Update the draft prompt (§10 VISUAL DIRECTION) to list the new
   keyword vocabulary explicitly so the LLM writes `visual:` strings
   that the classifier can match. Without this, the classifier sees
   unmatchable text and always falls through.

**Acceptance**
- A fixture set of `visual:` strings (zh-CN + en-US) classifies to the
  expected component for ≥80% of cases (manual set in tests).
- The benchmark `projects/benchmark-v01` article, after running
  `video draft` under v0.4, produces a storyboard with ≥3 distinct
  components across 6 scenes (was 1).

**Verification**
- Unit: `packages/draft/src/visual-classifier.test.ts` — table-driven.
- Integration: end-to-end draft → grep storyboard.yaml for component
  names → assert distinct count ≥3.
- Smoke: visually diff the rendered `preview.mp4` against the
  baseline — different scenes should look different.

### T3 · Image prompt expansion for `--image-provider minimax`
**Files**: new `packages/draft/src/image-prompt.ts`,
`packages/make/src/index.ts` (`generateSceneVisuals`).
**Goal**: when image generation is real AI (`--image-provider minimax`),
rewrite the article's 80-char `visual:` into a 2–3 sentence image
prompt (subject, environment, lighting, style). Cached by content hash.

**Steps**
1. New `image-prompt.ts` with:
   - `expandImagePrompt(scene, lang): Promise<{prompt, model}>` —
     cheap LLM call (≤200 output tokens, temperature 0.4).
   - System prompt: "You rewrite a one-line visual direction into an
     image-generation prompt. Subject · environment · lighting ·
     composition · style. No text overlays. No logos. No watermarks.
     Under 400 chars."
   - Output writes `assets/images/scene_N.prompt.txt` for audit.
2. Cache key: `sha256(visual|caption|narration[:200])`. Read cache
   first; only call LLM on miss.
3. In `generateSceneVisuals` (`packages/make/src/index.ts:258-313`):
   when `opts.provider === "minimax"`, call `expandImagePrompt` first;
   when `"mock"` or `"none"`, pass `visual:` verbatim (unchanged).
4. Add `tokens` / `estimated_cost_usd` to the existing `runs/*.yaml`
   record from `generateSceneVisuals` (currently `tokens: {0,0}`,
   `estimated_cost_usd: 0`). This was a stub.

**Acceptance**
- `video make demo --image-provider minimax` (real provider, with key)
  produces `assets/images/scene_*.prompt.txt` files alongside the JPGs.
- Re-running skips the LLM call (cache hit, no run record change).
- `video make demo --image-provider mock` produces no `.prompt.txt` and
  no LLM call.

**Verification**
- Unit: cache hit/miss, schema validation, prompt character-count
  cap.
- Integration: end-to-end with mock LLM provider returns canned
  expanded prompts; assert all scenes have `.prompt.txt`.
- Smoke: render twice, second render's `runs/*.yaml` shows zero
  tokens for the image step (cache hit).

### T4 · Hook ↔ YouTube package coherence
**Files**: `packages/youtube/src/agent.ts`, `packages/youtube/src/prompt.ts`,
`packages/cli/src/youtube-command.ts`.
**Goal**: the YouTube agent sees the article's hook explicitly and
generates a thumbnail prompt that's consistent with it. Also: tighten
the "no text overlay" rule.

**Steps**
1. Extend `YouTubeInput` with `hook: string` and `topic: string`
   (already implicit in `storyboard` but make it explicit).
2. In `buildYouTubeMessages`, place `## Hook (first 1–3 sentences)`
   before the storyboard excerpt — give the LLM the emotional tone
   it must echo in the thumbnail.
3. Update `SYSTEM_PROMPT` in `youtube/src/agent.ts`:
   - Add **negative constraints** explicitly: "NEVER include text,
     subtitles, watermarks, logos, or brand names in the thumbnail
     prompt. Output a generic visual scene, not a poster."
   - Add a **structural template** the LLM must follow:
     `[Person/subject] · [action/expression] · [environment] ·
     [lighting] · [mood] · [style modifier]`.
   - Same template for `shorts_hook` (it becomes a real beats list,
     not a freeform string).
4. Add `--from-article <path>` to `video youtube` (default: read hook
   from `projects/<slug>/article/article.md`).
5. Add a tiny output validator in `packages/youtube/src/agent.ts`
   that scans `thumbnail_prompt` for banned tokens
   (`["text", "字幕", "字体", "logo text", "标题"]`); if any match,
   retry once with the negative-constraint prompt (max 1 retry, no
   infinite loop).

**Acceptance**
- `video youtube <project>` (no flag) → `youtube/thumbnail-prompt.txt`
  begins with a person/scene description, not a text-overlay
  description.
- Validator catches and re-prompts when the LLM ignores the rule.
- `thumbnail-prompt.txt` and `shorts-hook.txt` reference the same
  emotional tone (curiosity / tension / surprise) as the article's
  hook — verified by a simple keyword-presence check in tests.

**Verification**
- Unit: validator token scan + retry path.
- Integration: end-to-end with mock provider that emits a
  text-overlay prompt first → assert retry produces a clean prompt.
- Smoke: render benchmark project → eyeball thumbnail prompt text.

**Steps**

**Acceptance**

  prints findings summary, run record written.
- `video final demo --force` on same → exits 0, prints `[FORCE] QA gate
  bypassed`.

**Verification**
- Unit: stub `buildRenderReport` to return canned error report →
  assert gate fires.
- Integration: create a project with a deliberate audio drift
  (scene duration 5s, audio file 7s), render, assert non-zero exit

Three waves, each shippable independently.

### Wave 1 — Quick wins (1 PR each, no new package)
- T1 (auto-captions) — `packages/draft` + `packages/cli`
- T8 (`--style`) — `packages/draft` + `packages/cli`
- T9 (CLI banner) — `packages/cli`

**Exit criteria**: `npm run acceptance` green; benchmark render

- T6 (QA gate in `video final`) — `packages/cli` + `packages/qa`
- T7 (QA surfacing in `video status`) — `packages/cli`

**Exit criteria**: benchmark storyboard has ≥3 distinct components;

- T4 (hook ↔ YouTube coherence) — `packages/youtube` + `packages/cli`
- T5 (scene-aware mock Shorts) — `packages/cli` + `packages/media`
- T10 (`video retrospect`) — optional new package

**Exit criteria**: `thumbnail-prompt.txt` and `shorts-hook.txt` pass
the validator's clean scan; mock `shorts.mp4` doesn't start on the
title card.

## 5. Risks & non-goals

### Risks
- **T2 (visual classifier) regression risk**: changing the storyboard
  shape breaks hand-edited storyboards. Mitigation: only auto-emit new
  components when the storyboard didn't already exist (i.e. first
  `video make` after `video draft`); preserve hand edits on subsequent
  runs (current behavior in `syncStoryboardFromArticle:245`).
- **T3 (image prompt expansion) cost**: every minimax render now
  spends extra tokens. Mitigation: cache key is deterministic;
  re-runs are free. First-render cost is bounded (≤200 output
  tokens × N scenes).
- **T6 (QA gate) UX risk**: existing users in the wild have
  un-gated `video final` muscle memory. Mitigation: gate only on
  `level: error`, not `warn`; `--force` preserves the escape.

### Non-goals (deliberately deferred)
- Local LLM / GLM image provider (no verified spec, doc §60).
- Per-segment BGM transitions (README "What's NOT here yet").
- Cloud rendering (infra-heavy, no spec).
- Removing or weakening the two-file human-gate model.
- Auto-publishing to YouTube / Shorts.
