# v0.7 Plan — Agent-Aware Draft Questions (`video-ask/1`)

Design source: this document (decision discussion 2026-10-15). Target
release: **v0.7**. Status: PLANNED — not started. Lands only after v0.6
(Laya) ships: the v0.6 work is uncommitted in the tree and must not be
entangled with this feature.

## 1. Summary

When `video draft` runs inside an agent harness (zcode, Claude Code,
pi, OMP, opencode, …), the CLI currently burns a full scored draft on
silent defaults — `zh-CN`, 180 s, `flat-vector`, `paper-light` — and a
wrong guess (especially language) costs a full regeneration (~4× a
single draft). This plan adds an **ask protocol**: the CLI detects the
agent from the environment and, when style knobs were left
unspecified, emits a machine-readable question set and exits 2. The
agent relays the questions through its native question UI
(highlighting the recommended option), then re-runs with explicit
flags.

Trigger model (user decision 2026-10-15): **auto-detect agent env** —
no flag cooperation required from the harness. Explicit `--ask` /
`--no-ask` and `VIDEO_ASK=` env remain as force/suppress overrides.

The load-bearing safety property: **questions are only ever emitted
for knobs the caller did not explicitly pass.** A replay script that
passes full flags never exits 2, even inside an agent session. This
kills the background-render-inherits-env footgun.

## 3. What this is NOT (rejected alternatives)

| Rejected | Why |
|---|---|
| Interactive TTY prompting (clack/prompts) | the repo is non-interactive by design; under an agent, stdin is the harness's pipe, not a human TTY |
| An answers file (`--answers answers.json`) | flags are already the CLI's config language; a second surface to parse and version buys nothing |
| CLI-side LLM call to compute topic-aware recommendations | extra spend + latency for what the presenting agent already knows; the agent owns the topic-aware upgrade (§8) |
| Laya involvement | a human preference is not a bounded decision; Laya stays an advisory decision layer for pipeline internals |
| `video make` / `video thumbnail` surfaces in v0.7.0 | look-and-feel flows downstream via article.md frontmatter written by draft; thumbnail can join in v0.7.1 if wanted |

## 4. Architecture

```text
video draft "<topic>"
  │ flag validation (unchanged — bad --file/--from still exit 1)
  │
  ├─ ask trigger active AND ≥1 knob unspecified? ──no──▶ normal run (byte-identical)
  │        yes
  ▼
  stdout: questions JSON (protocol video-ask/1)      exit 2
  ← BEFORE loadProviderConfig() / resolveProjectDir() /
    web search: zero spend, zero files written
  │
  ▼  agent asks the human (recommended option highlighted),
     maps answers → flags, re-runs:
video draft "<topic>" --lang zh-CN --duration 120 \
  --image-style editorial --style paper-light --bgm guofeng
  ▶ every knob explicit → zero questions → normal run
```

Wiring position in `runDraft`: one gate call immediately after input
validation, **before** `loadProviderConfig()` and project resolution —
the exit-2 path constructs no providers and touches no files.

### Trigger precedence

```text
--no-ask (flag)            → never ask
VIDEO_ASK=off              → never ask
VIDEO_ASK=force / --ask    → always ask (even without detection)
default                    → auto: ask iff agent env detected
                              AND ≥1 knob unspecified
```

Unknown `VIDEO_ASK` value: one stderr warning, treated as `auto`.

## 5. Protocol — `video-ask/1`

Exit codes: `0` ran · `1` failure (unchanged) · `2` questions pending —
**run did not start, nothing spent**.

In the ask path **stdout is pure JSON** (parseable with `jq`); all
human-readable hints go to stderr:

```text
agent-ask: 5 question(s) pending (exit 2 — run not started, nothing spent)
  re-run with the flags above, or --no-ask to accept the defaults
```

Full envelope (this block is the contract; field order is
snapshot-tested):

```json
{
  "protocol": "video-ask/1",
  "command": ["draft", "鸿门宴"],
  "detected": "zcode (ZCODE_APP_VERSION)",
  "questions": [
    {
      "id": "lang", "flag": "--lang", "type": "choice",
      "question": "Narration language?",
      "choices": [
        { "value": "zh-CN", "note": "Chinese narration (repo default)" },
        { "value": "en-US", "note": "English narration" }
      ],
      "default": "zh-CN", "recommended": "zh-CN",
      "why": "zh-CN is the silent default; a wrong guess costs a full regen (~4× one draft)"
    },
    {
      "id": "duration", "flag": "--duration", "type": "number",
      "question": "Target length in seconds?",
      "suggestions": [60, 90, 120, 180, 300],
      "default": 180, "recommended": 180,
      "why": "storyboard scene count scales with duration"
    },
    {
      "id": "image_style", "flag": "--image-style", "type": "choice",
      "question": "FLUX scene-image preset?",
      "choices": [
        { "value": "flat-vector", "note": "clean geometry; best cross-scene consistency" },
        { "value": "editorial", "note": "visual metaphor; history/abstract topics" },
        { "value": "whiteboard", "note": "marker sketch; pairs with draw-on animations" }
      ],
      "default": "flat-vector", "recommended": "flat-vector",
      "why": "editorial vs flat-vector is a taste call; neither is recoverable post-render"
    },
    {
      "id": "style", "flag": "--style", "type": "choice",
      "question": "Storyboard visual theme?",
      "choices": "<values from THEMES registry, each with a one-line note>",
      "default": "paper-light", "recommended": "paper-light",
      "why": "theme changes every scene"
    },
    {
      "id": "bgm", "flag": "--bgm", "type": "choice",
      "question": "Background music track?",
      "choices": [
        { "value": "calm", "note": "piano + strings, restrained; safe for any topic" },
        { "value": "epic", "note": "massed strings + timpani; dramatic topics" },
        { "value": "guofeng", "note": "Chinese folk orchestra; history/culture topics" },
        { "value": "liubang-xiaodiao", "note": "Han-dynasty folk motif; strong period flavor" },
        { "value": "fanzhuan-march", "note": "tension-building march; twist/reversal narratives" },
        { "value": "none", "note": "no BGM (bgm: null)" }
      ],
      "default": "calm", "recommended": "calm",
      "why": "BGM is generated per tag at make time; wrong mood is a paid re-render"
    }
  ],
  "resolved": {
    "lang": "zh-CN", "duration": 180, "audience": "developers",
    "image_style": "flat-vector", "style": "paper-light", "bgm": "calm"
  }
}
```

Field semantics:

- `protocol` — version tag; agents dispatch on it. Snapshot-tested.
- `command` — the argv that triggered the ask (echo, for context).
- `detected` — `"harness (VIA_VAR)"`, or `null` when forced via
  `--ask` without detection.
- `questions[]` — only **unspecified** knobs, stable order. Each has
  `recommended` (may differ from `default` in later versions) and,
  for choices, `{value, note}` objects so the presenting UI can show
  trade-offs. `why` explains why the question is worth asking.
- `resolved` — the full effective config (explicit + defaults), so
  the agent can show "keeping X" and pass a complete flag set.

`--ask` with nothing to ask: one stderr line
(`agent-ask: nothing to ask — all knobs explicit`), then the run
proceeds normally.

## 6. Question set

| id | flag | type | default | recommended | why asked |
|---|---|---|---|---|---|
| `lang` | `--lang` | choice | zh-CN | **zh-CN** | highest cost-of-error: wrong language burns a full scored draft (~4×) |
| `duration` | `--duration` | number | 180 | **180** | scene count scales with it (v0.5.3 behavior) |
| `image_style` | `--image-style` | choice | flat-vector | **flat-vector** | preset is a taste call, unrecoverable post-render |
| `style` | `--style` | choice | paper-light | **paper-light** | theme changes every scene |
| `bgm` | `--bgm` (NEW flag) | choice | calm | **calm** | wrong mood = paid re-render at make time |

`audience`, `model`, and the review-gate knobs stay flag-only power
knobs — deliberately not asked.

### `--bgm` semantics (new flag on `video draft`)

- Mirror of `--image-style`: the answered tag is stamped into the
  **fresh** `audio-config.yaml` as `bgm: <tag>` (for `none` →
  `bgm: null`), overriding the audio-plan LLM's pick for the `bgm:`
  key **only** — voice and SFX stay LLM-chosen.
- Existing `audio-config.yaml` wins (hand-edits invariant unchanged):
  the CLI prints `bgm answer not applied — audio-config.yaml kept;
  run 'video audio-plan' to regenerate` instead of overwriting.
- `--no-audio-plan` drops the `bgm` question entirely — never ask
  what cannot be applied (`questionsFor` sees the flag; still pure).
- Free-form tags remain legal end-to-end (`promptForTag` falls back to
  mood text), but the question offers only the 5 known tags + `none`.

## 8. Presentation rules (agent-side contract → video skill v1.5.0)

1. On `video draft` exit 2: parse stdout JSON; dispatch on
   `protocol === "video-ask/1"`.
2. Present the **recommended option first, labeled "(Recommended)"**;
   render each choice's `note` as its description.
3. The agent may replace the static recommendation with a topic-aware
   pick when the topic clearly demands it (e.g. 鸿门宴 →
   `liubang-xiaodiao` + `editorial`) and must state the reason in the
   question text. CLI stays deterministic; the agent, which knows the
   topic, owns the final highlight.
4. Five questions exceed the 4-per-call limit of zcode-style question
   UIs → present in two batches: narration (`lang`, `duration`,
   `bgm`), then look-and-feel (`image_style`, `style`).
5. Map answers → flags, re-run with the same topic. All knobs
   explicit → no second ask.
6. **Unattended sub-runs** (scripts a agent launches that call draft
   internally) pass `--no-ask`; headless cron/launchd shells set
   `VIDEO_ASK=off`.

## 9. Client contract (`packages/cli/src/agent-ask.ts`)

```ts
export interface AgentDetection { harness: string; via: string; }

/** Table-driven; first match wins; VIDEO_ASK_ENV consulted last. */
export function detectAgentEnv(
  env?: Record<string, string | undefined>,
): AgentDetection | null;

export interface AskQuestion {
  id: string;
  flag: string;                                   // "--lang"
  type: "choice" | "number" | "text";
  question: string;
  choices?: { value: string; note: string }[];    // style: "choice"
  suggestions?: number[];                         // style: "number"
  default: string | number;
  recommended: string | number;
  why: string;
  specified: (opts: DraftOptions) => boolean;     // explicit flag wins
  dropped?: (opts: DraftOptions) => boolean;      // e.g. bgm ⊄ --no-audio-plan
  resolved: (opts: DraftOptions) => string | number;
}

export const DRAFT_QUESTIONS: readonly AskQuestion[];

/** Pure: no fs, no providers, no I/O. Unspecified + not-dropped only. */
export function questionsFor(opts: DraftOptions): AskQuestion[];

export type AskTrigger =
  | { mode: "force" } | { mode: "off" } | { mode: "auto" };
export function resolveAskTrigger(
  opts: Pick<DraftOptions, "ask" | "noAsk">,
  env?: Record<string, string | undefined>,
): AskTrigger;

/** Prints the envelope to stdout + hint to stderr. Returns 2. */
export function emitQuestionsDoc(
  opts: DraftOptions, argv: string[],
): Promise<number>;

/** One call from runDraft, positioned per §4. Returns null (= run)
 *  or an exit code (2). Never throws. */
export async function maybeAgentAsk(
  opts: DraftOptions, argv: string[],
): Promise<number | null>;
```

`DraftOptions` gains `ask?: boolean`, `noAsk?: boolean`,
`bgm?: string`. Unit tests mock `process.env` objects; no test depends
on a live harness.

## 11. Test matrix (done-when for A1–A3)

1. No flags + fake agent env → exit 2; stdout parses as JSON;
   `protocol === "video-ask/1"`; exactly 5 questions; zero fs writes;
   no provider constructed.
2. Each knob passed explicitly → its question disappears; all five
   passed → normal run proceeds **under agent env** (exit ≠ 2).
3. `VIDEO_ASK=off` and `--no-ask` under agent env → normal run.
4. `--ask` (and `VIDEO_ASK=force`) without agent env → questions
   emitted, `detected: null`.
5. Unknown `VIDEO_ASK` value → stderr warning, treated as auto.
6. `--bgm guofeng` + fresh audio plan → config has `bgm: guofeng`,
   voice/sfx unchanged; `--bgm none` → `bgm: null`.
7. `--bgm` + existing audio-config.yaml → warning line, file
   byte-identical.
8. `--no-audio-plan` → no `bgm` question in the envelope.
9. `style` choices are generated from `THEMES` (adding a theme
   extends the question without code change).
10. stderr hint + `--ask` nothing-to-ask line snapshot-tested.

## 12. Risks

| Risk | Mitigation |
|---|---|
| Agent-launched unattended script inherits env → surprise exit 2 | fires only with an unspecified knob; §8 rule 6 (`--no-ask` in sub-runs, `VIDEO_ASK=off` for launchd/cron); distinct exit code |
| Agent that never read the skill treats exit 2 as a crash | self-describing JSON (`protocol`, `why` per question) + stderr hint naming the contract; skill covers the harnesses that matter |
| Detection list drifts as harnesses evolve | data table + `VIDEO_ASK_ENV`; unknown harness = today's behavior; first match wins is the only resolution rule |
| Human inside an inherited agent shell gets JSON instead of a video | rare; one command recovers (`--no-ask`); stderr hint says exactly that |
| Question fatigue (5 every draft) | only unspecified knobs asked; the driving agent usually has answers in context from the same conversation |

## 13. Non-goals (v0.7.0)

No interactive TTY prompting · no answers-file · `draft` only · no
Laya involvement · no answer memory across runs · no topic-aware
recommendations computed CLI-side.
