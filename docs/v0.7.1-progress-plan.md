# v0.7.1 Plan — Live Pipeline Progress (`video-progress/1`)

Design source: this document (user report 2026-10-15: "when running in
agents … I don't know what it is doing"). Target release: **v0.7.1**.
Status: IMPLEMENTED 2026-10-15.

## 1. Problem

`video make` prints its banner, then goes silent for the whole
pipeline — TTS (23 scenes), FLUX images (minutes each), render, mix —
and only prints the step report at the END (`make-command.ts` prints
`report.steps` after `runMake` returns). A 20–40 min run is
indistinguishable from a hang, especially for an agent polling a
background task's output file. `video draft` has the same shape at
smaller scale: silent during web search, the 1–3 min article call, and
the audio-plan call.

## 2. Principle

**Every silence gets a name and a clock.** Progress lines go to
**stderr** (stdout stays artifact-clean per video-ask/1), are **always
on** (the existing ✓ lines are already unconditional; agents and
humans read the same stream), and add **zero dependencies**.

## 3. Line vocabulary (stderr)

```text
  ▶ tts                        step start
  ✓ [3/23] tts scene_03  4.2s  item done (index/total when known)
  ⏳ generate-visuals … 95s     heartbeat: every 20s once a call passes 30s
  ✗ tts scene_07  12.1s: …     item/step failure (live; report still records it)
```

Marks reuse the `ui.ts` vocabulary (✓ / ✗ / ▷); ⏳ is new and means
"alive, waiting on one call". Elapsed is integer seconds everywhere.

## 4. Mechanism

1. `@video/make` exports `ProgressEvent`
   (`{kind: "start"|"done"|"fail"|"skip"|"heartbeat", label, elapsedSec?,
   index?, total?, message?}`) and `heartbeat(label, run, emit, opts)`
   — pure event emission, no printing (package stays library-quiet;
   default emit is a noop).
2. `runStep()` (the single choke point wrapping all 8 make steps) emits
   `start` → `done`/`fail` with elapsed, and wraps `run()` in a
   heartbeat. Dry-run and idempotent-skip paths emit nothing (the final
   report still shows them).
3. Scene loops emit per-item events: TTS loop (`runTts`) and visuals
   loop (`generateSceneVisuals`) carry `{index, total}`; cache hits
   stay silent. The heartbeat wraps each single image/TTS call, so a
   3-minute FLUX frame reads `⏳ image scene_07 … 95s`.
4. `packages/cli/src/ui.ts` gains `formatProgressEvent(e)` (the §3
   formatting) and `withProgress(label, run)` (heartbeat + start/done
   via stderr) for draft-command's three silent calls: web search,
   article draft, audio-plan. The judge already prints per attempt.
5. `make-command` passes `onEvent: (e) => console.error(formatProgressEvent(e))`
   into `runMake`; the final report table is unchanged — live lines
   supplement, never replace.

## 5. Non-goals

No spinners/TTY animation (breaks log files) · nothing on stdout · no
`--quiet` flag until something needs it · no structured progress from
the flux python worker (it already live-forwards its stderr) · no
machine-readable progress JSON (agents parse the human lines; exit
codes still carry success/failure).
