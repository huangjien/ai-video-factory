## 1. Summary

v0.8 adds guardrails around the least-reviewed part of the pipeline —
visual asset generation:

1. **Keyframe review**: `video visuals <project>` generates scene images +
   a Pillow contact sheet; `video approve visuals` / `video reject visuals
   <scene> <why>` gate the render. Opt-in per project via `article.md`
   frontmatter.
2. **Visual Bible**: named reference images declared in `article.md`
   frontmatter, conditioning flux via the existing image-to-image path
   (generalizes `--reference-style-anchor`).
3. **Stale propagation**: content-key the image cache (like TTS already is)
   and surface an impact table — exactly which images and scenes a `make`
   will re-run — before anything happens.

The signature property, stated once: **stale visuals never silently reach
the render, and approved visuals are never silently replaced.** Every image
on screen is either freshly generated from the current article, or a set a
human has explicitly approved.

## 3. What this is NOT (rejected alternatives)

| Rejected | Why |
| --- | --- |
| **Cost gates / budget metering** | user decision 2026-10-16: "not sensitive to cost". `runs/*.yaml` stays money-free; no price tables; nothing blocks on spend |
| PostgreSQL + approval dashboards, Next.js UI | the rejected design doc's architecture; this repo is CLI + files + `state.yaml` and stays there |
| Per-shot keyframe approval as a hard default | make is a one-command unattended pipeline (§65 two-file principle); a forced mid-make stop breaks scripted re-runs — gate is opt-in per project |
| Adding a `visuals` stage to `V01_STAGES` | frozen v0.1 contract consumed by checkpoint ids already on disk; piggyback on checkpoint files instead (D1) |
| A new config file (`cost-policy.yaml` / `visual-policy.yaml`) | one boolean does not justify a new file surface; frontmatter already carries pipeline behavior (`image_style`) |
| Auto-switching or auto-regenerating on drift without a report | silent self-healing hides article↔asset divergence; the impact table always shows the delta first |

## 4. Design decisions

### D1 — Where the visuals gate lives

- **Option A** — new `visuals` stage in the workflow state machine.
  Cleanest state semantics; breaks `V01_STAGES` consumers and existing
  checkpoint ids. Cost **M**, risk **high** (state files on disk).
- **Option B** *(recommended)* — a `video visuals` verb family +
  checkpoint record, no workflow change. `video visuals <project>` runs the
  existing `generate-visuals` step + builds a contact sheet;
  `video approve visuals` / `video reject visuals <scene> "<why>"` write a
  `checkpoints/visuals.yaml` record. When frontmatter enables the gate
  (D2), `video make` refuses to render unless the checkpoint's content-hash
  matches the current image set. Cost **S**, risk **low** — approve/reject
  verbs already exist as a family.

**Recommendation: B. Confidence: high.** The workflow package is a stable
contract; piggybacking keeps blast radius inside `make` + one new CLI verb.

### D2 — Gate opt-in surface

- **Option A** *(recommended)* — `article.md` frontmatter boolean:

  ```yaml
  ---
  require_visual_approval: true
  ---
  ```

  Same file the visual directions live in; the human editing images'
  source text is the human opting into image review. `image_style:`
  precedent (frontmatter already parametrizes generate-visuals).
- **Option B** — implicit: gate activates once any visuals checkpoint
  exists. No knob, but surprising — running `video visuals` once out of
  curiosity would permanently change make's semantics for that project.

**Recommendation: A. Confidence: high.** Explicit, visible in the file the
human already edits, trivially documented.

### D3 — Visual Bible declaration surface

- **Option A** *(recommended)* — `article.md` frontmatter maps scene
  numbers or roles to named refs; images live in
  `assets/visual-bible/<name>.png`:

  ```yaml
  ---
  visual_bible:
    style: paper-cut        # assets/visual-bible/style.png
    refs:
      char-xiaolin: { file: xiaolin.png, note: "蓝色连帽衫开发者" }
    scene_refs:
      "2,6,10": [char-xiaolin]
      "*": [style]
  ---
  ```

  `generateSceneVisuals` resolves a scene's refs to image paths and passes
  them through the existing `image=` conditioning (anchor machinery,
  `referenceStyleAnchor` becomes the special case `refs: [anchor]`).
- **Option B** — keep `--reference-style-anchor` only. Zero work, but one
  global look cannot express "this character appears in scenes 2/6/10".

**Recommendation: A. Confidence: medium** — the conditioning path exists and
is verified (T6.2), but per-image conditioning latency on 512–768px refs is
already documented as material; the plan ships refs as opt-in and keeps the
anchor flag untouched.

## 6. Test matrix (done-when)

- Staleness: editing `visual:` regenerates that image (fails on today's
  code — the regression this plan exists for); editing narration re-synths
  only that WAV; brand change still invalidates all scenes.
- Impact: dry-run names exactly the affected images/scenes for an edited
  article; storyboard-drift warning fires when article content changed but
  ids match.
- Gate: hash-mismatch refusal names stale scenes; reject-regenerate cycle
  converges; `require_visual_approval` absent ⇒ make is unchanged.
- Bible: frontmatter refs reach the worker as `image=`; no-frontmatter
  runs byte-identical.
- Compat: projects without frontmatter keys and without a visuals
  checkpoint behave exactly as v0.7.1 (golden-run comparison on
  `benchmark-v01`).

## 7. Rollout & compatibility

- All features default-off (no frontmatter keys, no checkpoint). v0.7.1
  behavior is the zero-config baseline.
- No changes to `V01_STAGES`, checkpoint id formats, or the two-file
  human-edit principle (`article.md` + `audio-config.yaml`) — the new
  frontmatter keys extend the existing human-edit file, they do not add a
  third surface.
- `video make` failure semantics unchanged: non-zero exit, no silent retry
  past bounded budgets.

## 8. Vertical slice (implement first)

**G1+G2** on the existing `skills-first` project: edit one scene's
`visual:`, run `make --dry-run`, see "scene_7 image regenerates, scene-07
re-renders, TTS untouched". Proves the signature end-to-end with zero
generation and zero surprises.

## 9. Deferred (explicitly out of v0.8)

- Full content-sync of storyboard from article edits beyond ids (the
  `sync-storyboard` early-return) — separate ticket; the impact-table
  drift warning (G2) surfaces it until then.
- Cost tracking in any form (user decision 2026-10-16 — revisit only if
  paid-provider usage grows).
- Per-image conditioning latency work (smaller refs, caching encoded refs).
- Multi-project visual-bible sharing at workspace level.
